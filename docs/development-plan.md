## 恢复开发顺序

每次由用户指定一项任务，取得对应证据、保存交接后结束。未知原因及缺少样本继续记录为未完成，不新增业务记录制造样本。

### 1. 抖音服务连接与导航

- **输入**：现有采集服务、T11 至 T13 连接诊断及误操作记录、当时系统和 App 版本；执行时重新核查设备及当前源码。
- **工作**：定位跨安装和跨测试进程的连接中断，核查官方活动窗口、节点更新、固定入口与动作范围；保持交易操作禁止。
- **完成条件**：分别记录已启用、已连接、采集状态与触摸模式；重复启动、停止、取消和进程重启后状态正确。只有确认连接中断才提示系统操作，自动恢复能力需要真实设备证明。
- **收益与成本**：减少重复授权和无效导航；需要设备、系统诊断和用户完成必要授权。

### 2. 抖音完整订单与物流读取

- **输入**：当前账号列表、两笔候选订单的原始资料，以及真实在途、跨年和多包裹样本。
- **工作**：补充完整下单时间和配送依据，验证返回列表后重新定位、重复卡片、平台明确结束状态与物流历史读取到底。
- **完成条件**：每项资料关联真实账号和订单编号；完整结束有官方页面证据，缺少字段保持 `PARTIAL`；两轮读取不增加重复订单、来源和轨迹。
- **收益与成本**：扩大可导入范围；依赖账号样本及页面可读取条件，缺少样本时保留对应未验证项目。

### 3. 京东与淘宝读取范围

- **输入**：当前有效会话、完整分页和已确认即时配送、待发货、充值及服务订单样本。
- **工作**：完成账号级分页与类型过滤验证，核查登录、安全验证和服务失败；补充早期字段变化的原始响应依据。
- **完成条件**：类型规则有业务字段或详情支持，普通快递与待发货保留；两轮结果和存量清理范围正确。无法补充的历史依据继续保留未确认状态。
- **收益与成本**：减少误导入及错误会话提示；需要真实服务可用、用户登录及相应订单样本。

### 4. 数据保留与系统行为

- **输入**：真实共享来源、别名、历史非空备注和归档副本，原生进度文件及当前系统调度记录。
- **工作**：补充迁移清理分支、进度密文损坏与版本不兼容、账号停用移除及 WorkManager 实际调度验证。
- **完成条件**：独立副本检查逐项字段和关系，业务提交与恢复标记一致，其他来源及用户字段保持；主库验证范围另行明确。
- **收益与成本**：补足数据保留及恢复证据；依赖历史样本和系统调度时间，独立副本需要额外保存空间。

### 5. 页面覆盖与 Jev 效果

- **输入**：真实取件码、未关联抖音订单、来源入口和 MainActivity 启动条件；按采集会话划分的独立验收资料。
- **工作**：补充复制、导航与启动联合流程；比较修正后的程序规则与 Jev 辅助判断的正确性、总耗时、人工介入及费用。
- **完成条件**：生产页面与数据库一致；交易操作全部拒绝，自动接受入口归属正确；相同条件比较后才声明整体改善。
- **收益与成本**：补足页面验收并量化模型价值；需要真实样本、重复验证和联网调用费用。

## 执行规则

平台读取解析、`LogisticsRepository` 事务保存和 `SyncCoordinator` 执行管理继续使用现有职责。公开平台接口、业务 Models、Room schema 或签名变化需要在对应任务中说明兼容要求。

每个后续任务采用[Jev 辅助规则](jev-workflow.md)：固定 `jev-1.14.0`，单次十秒，每阶段最多一百次，相同输入缓存；私人字段使用请求内编号。模型判断逐项核查，保存实际调用数、tokens、耗时和费用。页面自动采用保持至少 `0.95` 概率及当前窗口、节点和范围检查。

文档整理复用 T15 已核查资料，本次暂停交付没有新增 Jev 请求。T15 九项判断七项一致，达到门槛的五项一致；模型差异已经按原始资料复核。整体效果比较尚未完成。
