## 执行原则

- **设备操作全自动。** 打开应用、切换页面、点击、滚屏、截图、读取节点、写入系统设置全部由 adb、抖音采集服务、无障碍动作与识别结果驱动；执行过程不要求用户点按、登录、确认或观察。确实需要授权的项目由 shell 权限直接写入，并在验收记录写明写入的命令、修改前后的值与影响。
- **真实资料优先。** 订单、运单、轨迹和页面文本来自真实账号与真实页面；缺少样本时记录缺少条件并保持未完成，不构造订单、凭据或响应。
- **会话恢复按平台能力选择路径。** 平台提供免密授权（本机已登录的原生 App 授权跳转）时走授权；只提供短信验证码时由通知栏文本取得验证码并自动填入；两条路径都不可用时，改用该平台原生页面的只读采集，不保存也不猜测用户凭据。
- **先回归再扩展。** 修改公共流程前先运行受影响的既有测试，再增加新场景；每次设备执行前记录安装包指纹与数据库状态。
- **职责边界保持。** 平台读取与识别结果解析在平台层；业务写入、包裹合并与事务在 LogisticsRepository；账号锁、批次、期限与恢复在 SyncCoordinator。
- **证据与隐私。** 完整账号、订单、运单、地址与识别正文保存在本机忽略目录；公开仓库只保留源码、测试、公开文档与主 APK。
- **Pinky 手机操作。** 开发期手机界面操作、页面导航与页面证据采集默认使用[Pinky](pinky-workflow.md)的 MCP 手机操作工具；构建、安装、instrument 与数据库副本仍使用 adb。Pinky 任务与 instrument 测试、生产采集串行执行，读屏记录只保存在本机 `work/evidence/pinky/`，不作为验收证据。

**工作**：

1. 服务启用与状态：用 adb 把采集服务加入 enabled_accessibility_services，记录修改前后列表；启动抖音并确认服务连接状态为已连接。

**完成条件**：一轮执行后生产库出现该订单的运单与全部可识别轨迹，截图与识别正文保存在证据目录；同一订单再执行一轮不产生重复运单与重复轨迹；执行过程没有人工点按。2026-11-25 已满足：两轮分别 33.826 秒与 113.575 秒完成目标导入，轨迹 5 条，重复 0。

**影响与代价**：列表直达依赖数据库中保存的商品标题，只对已导入订单生效；新订单仍需要进入详情读取订单号。弹窗与列表使用窗口节点和范围手势，页面结构变化时错误会指出具体步骤。收益是抖音物流读取从八分钟期限缩短到一分钟内完成，后续平台可以复用同一套动作与识别组件。
